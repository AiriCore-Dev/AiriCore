# airi_point_salad 全面审计设计

## 目标

对 `plugins/airi_point_salad` 做完整、证据驱动的代码审计，重点验证本轮消息保留、双图桌面、轮次提醒、实时计分、50px 圆角和新手帮助改动，同时检查这些改动与既有游戏规则、事务、持久化、缓存和 NoneBot 适配层之间的交互。

审计阶段只发现和记录问题，不修改生产代码。全部审计完成后一次性修复所有确认问题，再统一验证。用户已授权无需中间确认。

## 范围

包含：

- `plugins/airi_point_salad` 下全部 Python、JSON、Markdown 和运行时素材引用
- 当前未提交差异及其直接调用方、被调用方
- NoneBot OneBot V11 消息发送、消息 ID 获取、撤回和异常路径
- 游戏状态模型、命令解析、状态机、技能、任务、计分和排名
- 存档加载、保存、回滚、超时与跨群并发
- 卡面、桌面、玩家卡组、轮次提醒和结算图片
- 运行时缓存、图片体积、最坏布局与资源生命周期
- `aps_help` 新手说明与实际指令、规则的一致性

不包含：

- 与 Point Salad 无调用关系的其他插件重构
- 美术素材主观重绘
- 外部平台真实群聊破坏性测试
- 未经证据支持的风格性重构

## 审计策略

采用分层审计：

1. Diff-first：逐行审查本次未提交差异，确认接口、状态和错误处理契约。
2. Call-chain expansion：从差异沿调用链向内核扩展，检查跨模块不变量。
3. Rule validation：用构造状态和完整对局覆盖官方规则、混合技能与当前分数。
4. Runtime validation：模拟 NoneBot 消息链、事务失败、并发和持久化恢复。
5. Rendering validation：检查视觉语义、布局边界、透明度、圆角、图片大小和缓存。
6. Repository regression：执行静态检查、插件加载与全部 20 种对局组合。

## 关键不变量

### 消息链

- 每群独立保留最近三组“用户输入 + Airi 回复”。
- 第四组到来时分别尝试撤回最旧的用户消息和 Airi 消息。
- 任一撤回失败不能阻止另一条撤回，也不能让当前命令失败。
- 无有效 Airi 消息 ID 时仍能正确清理用户消息。
- 游戏结束、超时、重载和多群并发不能造成无限增长或跨群误删。
- 轮次提醒图必须位于 `@下一位玩家` 之前，桌面图和玩家卡组图顺序稳定。

### 游戏与事务

- 无效命令、渲染失败和存档失败不留下半更新状态。
- 回合切换、行动后翻牌窗口、Center 技能和 Live Mission 语义保持原规则。
- 轮次变化提醒必须对应真正完成主行动的上一位玩家。
- 游戏结束时不错误提醒下一位玩家。

### 计分

- 预览总分与结算使用同一计分入口。
- 最多、最少和角色总数比较使用所有玩家的当前角色牌。
- 未来通配只影响指定计分牌，并正确进入该牌的全玩家比较上下文。
- Mission 分数、负分、0 张、并列和完整套组全部准确。

### 渲染

- 大厅桌面中央显示“游戏未开始”，同时玩家图可正常显示空卡组。
- 对局桌面与玩家卡组始终分别返回两张可解码的 `base64://` JPEG。
- 混合模式 Center 立绘以 20% Alpha 合成，按宽度覆盖并从顶部裁切。
- 玩家图对所有玩家展示计分牌背面、Q 版角色图标、数量和精确预览分数。
- 2–6 人、0–18 张计分牌、全部角色种类和最长用户名不越界或丢失关键内容。
- 卡牌最终 Alpha 蒙版使用 50px 圆角，缓存命中与冷建结果一致。
- 单张运行时图片不超过 OneBot 可接受的 3 MiB 目标。

### 文档

- `aps_help` 使用新手语言，先告诉用户如何开局和完成回合。
- 所有示例命令能被当前解析器接受。
- 普通/混合模式、翻牌窗口、结束条件和同分规则与实现一致。
- 不混入实现细节、存档格式或技术架构说明。

## 发现记录格式

每个发现包含：

- 严重度：P0、P1、P2 或 P3
- 文件和精确行号
- 可复现输入或状态
- 实际行为与期望行为
- 根因和影响范围
- 最小安全修复方向
- 对应回归测试

只有能由代码路径、自动化测试或可复现渲染证明的问题进入最终发现列表。纯偏好建议单独列为非阻塞改进，不与缺陷混排。

## 统一修复原则

- 审计发现冻结后再开始修改。
- 先为每个确认缺陷建立失败复现，再写最小修复。
- 不并发编辑同一文件，不做无关重构。
- 保持存档兼容、命令兼容和用户可见中文。
- 所有图片继续以 base64 发送，不引用本地路径。
- 测试产生的临时脚本、图片和字节码在验证后删除。

## 验证矩阵

- 消息保留：单群、多群、缺失回执、两条撤回各自失败、结束与超时清理
- 命令与事务：所有命令成功/失败路径、渲染失败、保存失败、并发同群操作
- 规则：十二类计分、六名 Center、四类 Mission、行动后翻牌窗口
- 完整对局：2–6 人 × quick/standard × classic/mix，共 20 种组合
- 渲染：大厅、普通/混合、2–6 人、0/1/9/18 张计分牌、最长名字、终局
- 静态与集成：Ruff、AST、隔离编译、`git diff --check`、Point Salad 插件加载、项目插件全量加载

## 完成标准

- 全部审计层完成，所有发现都有证据和严重度。
- 确认问题统一修复，定向回归从失败变为通过。
- 20 种完整对局保持终止、实体卡唯一和排名唯一。
- 最坏图片可解码且不超过体积目标。
- 静态检查、插件加载和差异检查全部通过。
- 最终报告明确区分已修复问题、未发现问题和剩余风险。
