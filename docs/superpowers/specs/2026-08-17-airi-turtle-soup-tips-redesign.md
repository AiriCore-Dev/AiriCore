# airi_turtle_soup tips 与判定标准重构设计

## 背景

`airi_turtle_soup` 现有 186 道题均使用 3 至 4 条字符串作为 `tips`。这些字符串主要复述汤底事实，但运行时同时将它们用于两种不同任务：判断玩家提问是否属于“精彩的提问”，以及判断玩家对汤底的还原程度。

现有结构无法区分宽泛但有效的探索方向和真正推进推理的关键突破。一些 tips 还是孤立关键词或直接答案，导致精彩提问判定依赖字面匹配，猜汤底判定则依赖模糊百分比和字数规则。

## 目标

- 重写全部 186 道题的 tips。
- 为每个关键事实分别描述事实本身、有效探索方向、精彩提问条件和完成度权重。
- 在模型内部区分普通有效探索和关键突破，但只向玩家展示“精彩的提问”。
- 优化提问判定与猜汤底判定提示词，使结果稳定、无阈值空档并兼容现有处理器输出。
- 保持现有汤面、汤底、指令和游戏流程不变。
- 不恢复已经删除的生成 tips 与生成整题提示词。

## 非目标

- 不修改现有汤面和汤底内容。
- 不新增玩家可见的“好问题”文案。
- 不恢复或重写 `generate_tips.md` 和 `generate_turtle_soup_prompt.md`。
- 不改变每日次数、个人次数、总轮询次数或胜利结算逻辑。

## 数据结构

每道题的 `tips` 保持为数组，但数组元素由字符串改为对象：

```json
{
  "fact": "男人是灯塔管理员，负责灯塔运转",
  "direction": "男人的职业和职责与自杀原因有关",
  "breakthroughs": [
    "询问男人是否从事灯塔相关工作",
    "询问男人是否对某种照明或航海安全设施负责",
    "询问他的自杀是否与工作失职有关"
  ],
  "weight": 25
}
```

字段约束：

- `fact` 是汤底中的必要事实，用于猜汤底覆盖度判定。
- `direction` 是有效探索所触及的推理维度，用于模型区分普通有效问题和无推进问题。
- `breakthroughs` 包含 2 至 5 个可独立命中的精彩提问条件。
- `weight` 是正整数，同一道题全部关键事实的权重总和必须为 100。
- 每道题包含 3 至 5 个关键事实。
- 所有内容必须能从本题汤底得到支持，不得补充汤底之外的设定。

## 提问判定

提问判定继续以汤面和汤底为事实来源，并使用结构化 tips 判断问题价值。

基础输出保持为以下一种：

- `是`
- `不是`
- `无关`
- `是又不是`
- `你需要自己进行猜测`

判定顺序：

1. 判断玩家是否在直接索要完整答案、原因或真相。此类输入回答 `你需要自己进行猜测`。
2. 对可封闭判断的问题，依据汤底判断 `是`、`不是`、`无关` 或 `是又不是`。
3. 判断问题是否语义命中任意关键事实中的任意一个 `breakthroughs` 条件。
4. 命中时在基础回答后另起一行追加 `精彩的提问`，同一问题最多追加一次。

精彩提问判定遵循以下规则：

- 允许同义表达、合理概括、上位概念和不同句式，不要求原词一致。
- 玩家不需要同时命中同一关键事实的全部条件，命中任意一个即可。
- 仅触及 `direction` 代表问题方向有效，但不追加玩家可见文案。
- 复述汤面已知信息、泛泛询问某事是否重要、没有实质限定的提问不算精彩。
- 一个问题包含多个命题时，基础回答仍按整体真假关系判定；只要其中存在明确命中的关键突破条件，仍可标记一次“精彩的提问”。

## 猜汤底判定

模型根据玩家答案对各项 `fact` 的语义覆盖情况累计 `weight`。同义表达、合理概括和不同叙述顺序均视为覆盖，不要求逐字匹配。

判定区间：

- 覆盖度不低于 75%：`猜测成功`
- 覆盖度为 50% 至 74%：`很接近了`
- 覆盖度为 25% 至 49%：`马马虎虎`
- 覆盖度低于 25%：`猜得不对`

四分位阈值使四个等权关键事实中命中三个即可过关，同时避免只猜中一半就直接结束游戏。若玩家答案明确否定核心身份、隐藏条件或因果关系，即使覆盖度达到 75%，结果最高只能为 `很接近了`。

删除现有“输入少于十个字必定失败”的规则。简洁但完整的答案按实际语义覆盖度评分。

## 运行时适配

- `helpers.py` 不再读取已经删除的生成整题提示词。
- 提问与猜汤底处理器不再使用 `"\n".join(soup["tips"])`。
- 新增统一的 tips 序列化入口，将结构化 tips 以保留中文的 JSON 文本传入提示词。
- 题库加载时仍要求顶层为列表，并增加结构化 tips 校验，避免损坏数据进入运行时。
- 提问与猜汤底处理器现有重试、次数返还、并发身份校验和胜利判断流程保持不变。
- 猜汤底成功输出仍以 `猜测成功` 开头，兼容现有 `startswith` 胜利判断。

## 题库重写原则

每道题先从汤底拆解完整推理链，再生成结构化 tips：

1. 识别人物身份、场景条件、行为目的、隐藏事件、关键因果和最终结果。
2. 只保留还原汤底不可缺少的 3 至 5 个事实。
3. 按事实对完整解释的重要程度分配权重，总和为 100。
4. 为每个事实写一个比答案更宽的 `direction`。
5. 为每个事实写 2 至 5 个具体但可泛化的 `breakthroughs` 条件。
6. 检查条件是否能覆盖玩家自然提出的不同问法，同时避免把“这个重要吗”一类泛问误判为精彩。

## 验证

结构验证覆盖全部 186 道题：

- 每题 `tips` 为 3 至 5 个对象。
- 每个对象包含且只包含 `fact`、`direction`、`breakthroughs`、`weight`。
- 所有文本字段非空。
- 每个 `breakthroughs` 为 2 至 5 个非空字符串。
- 所有 `weight` 为正整数且每题总和为 100。
- 全部题库可被项目加载。

内容验证覆盖全部题目，并重点抽查不同类型题目：

- 每条 `fact` 均能在汤底中找到依据。
- `direction` 不直接替代完整汤底。
- 每个精彩条件都代表能够显著缩小推理范围的问题。
- 同一关键事实的条件不存在纯同义重复。
- tips 之间共同覆盖汤底核心身份、条件和因果链。

判定边界验证至少覆盖：

- 明确命中精彩条件的肯定问法。
- 使用同义词命中精彩条件的问法。
- 只触及方向但不够具体的普通有效问题。
- 泛泛询问“是否重要”的问题。
- 与故事无关的问题。
- 部分正确、部分错误的复合问题。
- 直接索要真相的问题。
- 覆盖度分别落在 24%、25%、49%、50%、74% 和 75% 附近的猜汤底答案。
- 高覆盖但明确否定核心因果关系的答案。

验证期间临时创建的脚本和结果在验证结束后删除，不保留为项目文件。

## 用户可见行为

普通有效问题仍只收到基础真假回答。只有达到关键突破标准的问题才会收到：

```text
是
精彩的提问
```

其余游戏流程和玩家指令不变。
