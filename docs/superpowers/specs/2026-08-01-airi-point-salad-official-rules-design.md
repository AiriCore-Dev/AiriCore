# Airi Point Salad 官方规则与卡组设计

## 目标

将 `airi_point_salad` 的普通模式改为官方 Point Salad 基础规则，并让混合模式在同一官方引擎上叠加现有 Center 与 Live Mission。卡牌继续使用 MORE MORE JUMP！主题美术，但卡池、计分条件、牌堆结构、补牌、翻牌和终局判定以官方资料为准。

## 已确认范围

- 保留 2–6 人群聊玩法、现有根命令与中英文缩写。
- 保留快速局和标准局。两者只改变本局抽入的官方卡牌数量，不改变规则。
- 保留普通模式和混合模式。
- 普通模式只运行官方基础规则；标准局使用官方人数牌量，快速局是减少牌量的官方引擎变体。
- 混合模式在官方基础规则上启用现有 Center 与 Live Mission。
- 快速局每种角色使用 `玩家数 × 2` 张牌，总牌数为 `玩家数 × 12`。
- 标准局每种角色使用 `玩家数 × 3` 张牌，总牌数为 `玩家数 × 18`。
- 6 人标准局使用完整 108 张官方卡牌。
- 卡牌信息逐张写入 `plugins/airi_point_salad/assets/cards.json`。
- 计分牌保留主题底图和角色素材，但信息结构、图标关系和相对位置仿照官方卡面。
- 帮助内容可以完全重写。
- 重写 `plugins/airi_point_salad/aps_help/index.mdx` 文章及其规则配图。
- 不迁移旧存档。旧格式主档与备份直接删除。

## 官方资料结论

- 官方卡组有 108 张双面卡，甘蓝、胡萝卜、生菜、洋葱、甜椒、番茄各 18 张。
- 计分面包含 108 个不同条件。
- 官方使用三叠独立牌库，每列市场只从对应牌库补牌。
- 空牌库从当前最大牌库拆分，移动其下半部分并保留原牌库顶部卡牌。
- 每回合可拿一张计分牌或两张蔬菜牌。
- 每回合最多把一张自己的计分牌永久翻成蔬菜面，允许翻本回合刚取得的计分牌。
- 普通模式随机决定起始玩家。
- 所有牌库与市场均清空时结束。
- 总分并列时，行动顺序较晚的玩家获胜。

## 主题映射

官方蔬菜名和稳定 ID 保留在 JSON 中，运行时通过显式映射转换为现有六名角色：

| 官方蔬菜 | 主题角色枚举 |
|---|---|
| cabbage | haruka |
| carrot | shizuku |
| lettuce | minori |
| onion | airi |
| pepper | rin |
| tomato | miku |

映射只改变展示与角色牌分类，不改变官方卡牌条件。JSON 中的计分参数始终引用官方蔬菜键，加载后再转换为 `Character`。

## 卡牌 JSON

`assets/cards.json` 使用一个版本化根对象：

```json
{
  "schema_version": 1,
  "produce_mapping": {
    "cabbage": "haruka",
    "carrot": "shizuku",
    "lettuce": "minori",
    "onion": "airi",
    "pepper": "rin",
    "tomato": "miku"
  },
  "cards": [
    {
      "id": "CAB-01",
      "produce": "cabbage",
      "source": "p1-r1c1",
      "rule": {
        "type": "most",
        "target": "carrot",
        "points": 10
      }
    }
  ]
}
```

加载器严格验证以下条件：

- `schema_version` 必须为 1。
- 只允许六个官方蔬菜键和六个现有角色枚举值。
- 卡牌 ID 唯一且必须覆盖 `CAB/CAR/LET/ONI/PEP/TOM` 的 `01–18`。
- 卡牌总数必须为 108，每种蔬菜面必须为 18 张。
- `source` 必须唯一覆盖卡片 PDF 第 1–12 页的全部 108 个格位。
- 规则类型和字段严格匹配，不接受隐式类型转换、未知字段或非有限数值。

官方规则类型为：

- `most`
- `fewest`
- `parity`
- `linear`
- `same_pair`
- `same_triple`
- `set`
- `missing_types`
- `types_at_least`
- `fewest_total`
- `most_total`
- `complete_set`

代码不得再次按索引生成或修改计分条件。随机过程只负责从每种蔬菜的 18 张官方牌中选择本局子集并洗牌。

## 状态模型

`GameState` 使用三叠牌库替代共享 `deck` 和独立 `score_market`：

- `decks: list[list[str]]` 固定包含三叠，列表末尾为牌堆顶部。
- 每叠顶部卡牌即公开的计分牌，不再复制到其他字段。
- `character_market` 继续保存三列两行市场，每个空位从同列牌库顶部翻入。
- `starting_player` 保存随机先手索引。
- `PlayerState.last_action_turn` 记录该玩家最后完成主行动的唯一顺序号，用于官方平分判定。
- `post_flip_user_id` 表示上一名刚完成主行动、仍可在下一名玩家首次有效行动前补做翻牌的玩家。
- `post_flip_available` 表示该玩家本回合尚未使用翻牌机会且没有被技能禁止。

普通模式不创建 Center、Mission 或技能待处理状态。混合模式沿用这些字段并在官方状态机之上工作。

## 牌库构建与开局

1. 按速度计算每种角色所需数量：快速为 `人数 × 2`，标准为 `人数 × 3`。
2. 从每种蔬菜面的 18 张官方牌中使用本局种子等量随机抽取，抽取过程不参考计分条件。
3. 合并并洗匀所选卡牌。
4. 依次分入三叠，使三叠数量差不超过 1。
5. 每列从对应牌库顶部翻两张进入角色市场。
6. 使用同一本局随机源选择起始玩家。
7. 混合模式随后分配 Center 并初始化 Live Mission。

相同玩家、速度、模式和种子必须得到完全一致的卡组、三叠顺序与先手。

## 市场补牌与空堆拆分

所有补牌都遵循列级来源：

1. 玩家拿牌后，先处理空牌库。
2. 对每个空牌库，选择其他牌库中卡牌数最多的一叠。
3. 最大牌库并列时选择列号较小的一叠，保证确定性。
4. 最大牌库少于 2 张时不再拆分。
5. 将最大牌库底部的 `len(deck) // 2` 张按原顺序移动到空牌库，原最大牌库顶部保持不变。
6. 再按列为市场空位补牌。
7. 补牌导致牌库再次变空时重复拆分，直到所有可补位置已补或剩余卡牌不足以拆分。

Haruka 的刷新列技能改为只操作目标列：移除该列当前顶部计分牌和市场角色牌，把这些牌按稳定顺序放到该列牌库底部，再按官方列级规则补牌。其他 Center 技能保持原语义。

## 回合与翻牌

现有拿牌和翻牌命令保持不变，不新增显式结束回合命令。

- 当前玩家可在主行动前使用 `,sl fl 编号`，随后仍可拿牌。
- 主行动完成后立即把回合指针移到下一名玩家，并为刚行动玩家开启后置翻牌窗口。
- 在下一名玩家首次成功执行会改变游戏状态的回合动作前，上一名玩家仍可使用 `,sl fl 编号`。
- 后置翻牌可选择本回合刚取得的计分牌或此前取得的计分牌。
- 下一名玩家首次成功执行翻牌、拿牌、技能准备或技能结算时，上一名玩家的窗口关闭。
- 查看桌面、查看帮助、无效命令和失败操作不关闭窗口。
- 一个玩家在同一回合的前置翻牌和后置翻牌合计最多一次。
- Airi Center 当前禁止翻牌的回合不创建后置窗口。

这一适配保留现有一条主行动指令即可自动换人的群聊体验，同时覆盖官方允许“拿到后再翻”的规则。

## 终局与平分

- 三叠牌库和六个市场位置全部为空时结束。
- 残局市场不足两张时，拿角色牌动作必须拿走所有剩余角色牌。
- 每名玩家完成主行动时写入递增的 `last_action_turn`。
- 排名首先按包含 Mission 的最终总分降序。
- 同分时按 `last_action_turn` 降序，行动较晚者胜出。
- 不再使用角色牌数量或 Mission 数量破同分。
- 每个名次唯一，不产生共享排名。

## 官方计分引擎

计分上下文包含当前玩家角色数量、所有玩家角色数量、所有玩家角色总数和 Miku Center 的单牌通配修正。

- `most/fewest`：与所有玩家比较目标角色数量，并列满足条件。
- `parity`：偶数得 7 分，奇数得 3 分，0 视为偶数。
- `linear`：各角色数量乘相应系数后相加，允许负分。
- `same_pair/same_triple`：目标数量分别除以 2 或 3 后向下取整，再乘组分。
- `set`：指定角色各一张组成一组，组数取各角色数量最小值。
- `missing_types`：数量为 0 的角色种类数乘分值。
- `types_at_least`：达到阈值的角色种类数乘分值。
- `most_total/fewest_total`：比较全部角色牌总数，并列满足条件。
- `complete_set`：六种角色数量最小值乘 12。

Miku Center 的通配只修改指定计分牌的当前玩家计数。比较型规则会把该临时计数与其他玩家真实计数比较，不污染其他计分牌和最终持牌统计。

旧 `each/pair/set/compare/risk` 生成规则不再用于新对局。由于旧存档直接删除，运行时无需保留旧规则兼容路径。

## 卡牌渲染

保留现有 `front_base`、`back_base`、角色立绘、Q 版头像、标题、金边、圆角和缓存机制。

计分面按官方卡牌结构重新布局：

- 左上角和右下角放置代表翻面角色的三角角标与小头像。
- 中央保留大面积浅色盘面作为信息容器。
- `most/fewest` 使用条件词、目标头像、分值徽章的横向结构。
- `parity` 使用上下两行“偶数/奇数 + 分值徽章”。
- `linear` 每个系数和头像独占一行，正负系数使用明确符号和对比色。
- `same_pair/same_triple` 使用重复头像、加号、等号和分值徽章。
- `set` 使用角色头像横排、加号、等号和分值徽章。
- `missing_types/types_at_least` 使用中文条件文字、阈值和每种分值徽章。
- `most_total/fewest_total` 使用全场总数条件与单一分值徽章。
- `complete_set` 展示六个角色头像和每套 12 分。
- 卡牌底部保留稳定卡牌 ID，便于问题定位。

官方卡面的信息层级、图标关系、运算符和相对位置作为版式依据，但不复制官方绿色背景或蔬菜美术。

桌面顶部三张计分牌直接渲染三叠牌库顶部。牌库剩余数量按列显示，玩家可以看出每列公开信息和剩余规模。

## 帮助与用户提示

- `,sl` 速查说明快速/标准只影响牌量，普通/混合只影响扩展内容。
- `,sl rl` 重写为官方基础规则、快速变体、混合扩展、三叠补牌、翻牌窗口、计分类型、指令示例和版权信息。
- 普通模式帮助不出现 Center 或 Mission 规则。
- 混合模式帮助明确它们是叠加在官方基础规则上的自定义扩展。
- 所有用户可见错误和日志继续使用中文。
- 现有帮助封面继续通过 base64 发送。

## 存档策略

新存档根对象增加 `schema_version`，状态模型使用三叠牌库和新的回合字段。

- 加载时逐个识别主档、备份和旧 JSON 存档；属于旧格式的文件直接删除，不尝试转换或隔离。
- 若不存在任何可用的新版本主档或备份，则返回空对局集合。
- 新版本主档仍使用纯字典 pickle、受限 Unpickler、原子替换和新版本备份。
- 新版本主档损坏时仍按现有安全策略尝试新版本备份；主备均坏时隔离损坏文件并从空状态启动。
