# airi_astral_party 设计规格

## 目标

`airi_astral_party` 是 AiriCore 的《吉星派对》综合查询插件。首版只支持国服 `CN`，同时提供玩家实时查询与客户端静态资料查询，并以客户端资源生成图片结果。

插件以玩家 UID 为唯一游戏账号输入。QQ 用户可以绑定一个 UID 后使用 `astral me` 系列命令，也可以通过 `astral CN <UID>` 直接查询其他玩家的公开数据。实时查询由插件内置的专用游戏账号维持一条长期 TCP 会话，查询用户不需要提供游戏凭据。

## 已确认范围

- 统一命令入口为 `astral`。
- 首版只接受 `CN`，内部接口保留服务器维度。
- 一个 QQ 绑定一个游戏 UID。
- 静态资料和玩家实时数据均纳入插件。
- 查询结果优先输出图片，失败时降级为中文结构化文本。
- 建立客户端资源维护系统，使用官方 Addressables 和 GameData。
- 专用查询账号在 AiriCore 运行期间持续在线。
- 专用账号必须与前期研究使用的个人账号不同。
- 不绕过服务端权限，不实现隐藏管理能力。

## 非目标

- 首版不支持 `CN` 以外的服务器。
- 不要求普通查询用户登录游戏或提交 token。
- 用户凭据上传与私有数据查询本轮只预留入口，不实现接收、解析或持久化。
- 不提供修改玩家资料、领取奖励、发起好友请求等写操作。
- 不伪造硬件证明，不绕过反作弊、风控或服务端权限检查。
- 不把个人账号抓包、专用账号 token 或完整认证报文提交到仓库。

## 命令设计

### 账号管理

| 命令 | 行为 |
| --- | --- |
| `astral bind CN <UID>` | 校验 UID 后将当前 QQ 绑定到该国服账号 |
| `astral bind` | 查看当前 QQ 的绑定状态 |
| `astral unbind` | 解除当前 QQ 的绑定 |

`CN` 大小写不敏感。其他服务器统一返回“当前仅支持国服 CN”。重复绑定会覆盖旧绑定，并在结果中展示旧 UID 与新 UID。绑定校验失败、实时服务未认证或官服不可用时不修改原绑定。

QQ 身份直接取 OneBot 事件的 `user_id`，不从用户输入解析。绑定持久化使用本地数据文件，不依赖 Kokomi 的外部绑定 API。

### 用户凭据入口预留

为后续查询用户自己的私有详细数据，保留 `astral auth upload` 作为用户凭据入口。当前版本不接受命令参数、文件、token 或截图，不读取消息中的凭据内容，只返回“该功能尚未开放”的提示。

后续实现必须将用户凭据与专用查询账号完全隔离，以 QQ 和 UID 作为明确归属，提供撤销、替换、过期和状态查询能力，并沿用认证数据的脱敏日志、最小权限、原子持久化和删除机制。本入口的预留不改变当前“普通 UID 查询只依赖专用账号”的行为。

### 玩家查询

| 命令 | 行为 |
| --- | --- |
| `astral me` | 查询已绑定账号总览 |
| `astral me char [页码] [refresh]` | 查询角色数据 |
| `astral me skin [页码] [refresh]` | 查询皮肤数据 |
| `astral me record [页码] [refresh]` | 查询对局记录 |
| `astral me show [refresh]` | 查询公开展示信息 |
| `astral CN <UID>` | 查询指定 UID 的账号总览 |
| `astral CN <UID> char [页码] [refresh]` | 查询指定 UID 的角色数据 |
| `astral CN <UID> skin [页码] [refresh]` | 查询指定 UID 的皮肤数据 |
| `astral CN <UID> record [页码] [refresh]` | 查询指定 UID 的对局记录 |
| `astral CN <UID> show [refresh]` | 查询指定 UID 的公开展示信息 |

省略页码时使用第 1 页。`refresh` 必须位于末尾。页码必须是正整数。总览、角色、皮肤、战绩和展示信息均通过同一个目标解析接口执行，`me` 与显式 UID 只在目标来源上不同。

角色与皮肤命令只展示服务端对该 UID 合法公开的数据。如果服务端只返回展示角色、拥有数量或部分资料，结果必须明确标注“公开可见”，不得把静态 GameData 中的完整列表误报为玩家已拥有内容。

后续发现新的合法 UID 查询能力时，通过注册新的玩家子命令扩展，不改变现有语法。候选能力必须先在专用账号上验证请求字段、权限和响应语义。

### 静态资料查询

| 命令 | 数据源 |
| --- | --- |
| `astral char <名称>` | `Character`、`STRCharacter` 及关联技能和素材 |
| `astral skill <名称>` | `Skill`、`STRSkill` |
| `astral card <名称>` | `Card`、`STRCard` |
| `astral item <名称>` | `Item`、`STRItem` |
| `astral map <名称>` | `Map` 及关联本地化数据 |
| `astral activity <名称>` | `Activity` 及关联任务和奖励数据 |
| `astral search <关键词>` | 跨表名称和别名搜索 |

静态查询只访问当前已激活的本地资源，不占用专用账号连接。名称匹配依次尝试精确名称、规范化名称、别名和模糊搜索。多条匹配返回带编号的候选列表，不擅自选择不同对象。

## 总体架构

插件分为以下边界清晰的组件：

1. 命令适配层：解析 `astral` 语法、提取 QQ 身份、规范化服务器和 UID。
2. 绑定仓库：维护 QQ 到 `(server, uid)` 的一对一映射。
3. 资源发现器：按照客户端流程发现 CDN 版本和 catalog。
4. 资源仓库：下载、验证、激活和回滚 GameData 与 Addressables 资源。
5. 静态数据服务：读取 GameData 表，提供跨表关联和文本搜索。
6. 认证仓库：保存专用账号的必要认证字段和固定设备画像，并为未来的用户凭据提供隔离的凭据提供者接口。
7. TCP 会话客户端：负责连接、帧编解码、心跳、推送和重连。
8. 玩家查询服务：把功能请求映射为协议 RPC，合并静态资料并执行缓存策略。
9. 图片渲染器：用客户端素材生成分页图片并编码为 base64。
10. 运行诊断：提供脱敏日志、连接状态、资源版本和队列指标。

命令层不直接操作网络、文件或 Protobuf。资源版本、连接状态和查询结果都通过明确接口暴露，使协议变化、素材变化和渲染变化可以独立处理。

## 已确认的官方协议基础

### HTTP 与资源 CDN

当前国服客户端版本为 `3.2.0`，平台路由为 `CN_ANDROID`。已确认以下资源发现流程：

- 登录图：`GET http://se-web-cn.feimogames.com:7878/api/loginImage/get?route=CN_ANDROID&version=<version>`
- 资源版本：`GET http://se-web-cn.feimogames.com:7878/api/hotaddressExtend/get?route=CN_ANDROID&version=<version>`
- catalog：资源根目录下的 `catalog_<version>.hash` 和 `catalog_<version>.json`

资源版本接口返回的 `sourceUrl` 是当前 CDN 根目录。插件不得写死当前构建号，必须从版本接口发现。

### Addressables 与 GameData

当前 catalog 已确认包含约 1.3 万个 key 和约 6000 个 bundle internal ID。`GameData_CN` bundle 内含 153 张 Protobuf 表，包括角色、技能、卡牌、物品、皮肤、地图、活动、任务、遗物和怪物等数据。

热更新托管 DLL 中已恢复 160 个 Protobuf descriptor，协议映射目前包含 455 个消息号。这些研究资料保存在插件目录的 `tmp/research` 中，不作为生产运行数据，也不包含个人账号的原始认证抓包。

### TCP

当前国服地址为 `101.132.186.71:8800`。连接采用未额外加密的 TCP 与 Protobuf，帧头固定为 35 字节：

- offset 0：4 字节大端 body 长度
- offset 12：2 字节大端消息号
- offset 24：4 字节小端序列号
- offset 35：Protobuf body 起点

已确认的基础消息包括：

- `5001/5002`：`ConnectC2S` / `ConnectS2C`
- `5003/5004`：`HeartbeatC2S` / `HeartbeatS2C`
- `5263/5264`：`GetPlayerSimpleC2S` / `GetPlayerSimpleS2C`
- `5153/5154`：`GetShowPlayerC2S` / `GetShowPlayerS2C`
- `5155/5156`：`GetPlayerFightRecordC2S` / `GetPlayerFightRecordS2C`
- `5185/5186`：`SearchPlayerC2S` / `SearchPlayerS2C`

心跳间隔为 10 秒。实际功能映射以专用账号认证后的脱敏集成验证为准，不能仅依据消息名称推断响应字段含义。

## 专用账号与客户端行为

### 固定客户端画像

插件不修改 AiriCore、安卓模拟器或宿主系统的运行环境，只在官方请求所需字段中使用固定的安卓客户端画像。插件不自行生成设备身份；用户通过官方客户端登录专用账号并采集认证流程时，同时提取该次请求实际携带的设备字段和安装字段。

专用账号凭据与设备画像写入同一个 `data/airi_astral_party/auth_profile.pk` 认证档案。档案内部区分可按正常认证流程更新的凭据区与不可自动变化的设备区。之后所有启动、登录、查询和重连均读取该档案；采集完成前，实时查询保持 `AUTH_REQUIRED`。

固定设备区只保存协议确实使用的设备标识、安装标识、Android 版本、机型、语言和时区。应用版本、资源版本和国服路由属于协议状态，可以随官方版本更新，不视为设备身份变化。设备字段不得按请求随机化，也不得因 AiriCore 重启、插件升级、资源更新、凭据刷新或普通认证失败而重新采集或改写。

认证档案使用校验和、主副本和同目录原子替换持久化。凭据正常刷新时必须验证设备区内容和校验值保持不变。主文件损坏时只允许从内容一致且校验有效的副本恢复；两份均不可用时，实时查询进入 `AUTH_REQUIRED` 并通知管理员，不得静默生成新身份。未来如需重置，必须由管理员执行明确的人工重置流程。

客户端画像用于协议兼容，不用于伪造硬件证明或绕过服务端安全校验。若官方流程要求当前实现无法合法提供的设备证明，实时查询进入认证不可用状态。

### 认证采集

只有在实现认证适配阶段，才通知用户登录新建的专用账号并重新抓包。采集过程同时提取建立 `ConnectC2S` 所需的账号凭据和官方请求实际携带的设备信息，将两者组成认证档案，完成后生成脱敏研究结果。前期个人账号 token 和设备信息不得打印、复制或复用。

认证数据保存在 `data/airi_astral_party/`，文件权限限制为当前运行用户可读写。源码、Git 历史、普通日志、错误消息和查询结果不得包含 token。原始含凭据抓包不进入插件目录。

本轮不实现 `astral auth upload` 的任何凭据处理逻辑。未来用户凭据不得复用专用账号的会话或设备画像，必须单独建立授权范围、会话生命周期和数据清理策略。

### 会话生命周期

会话状态为：

`AUTH_REQUIRED -> CONNECTING -> ONLINE -> BACKOFF`

AiriCore 启动时加载认证数据并建立唯一国服长连接。进入 `ONLINE` 后，每 10 秒发送一次协议心跳，同时持续读取并解析服务端推送。所有玩家 RPC 经同一个有界请求队列发送，不为单次查询重复登录。

普通网络错误采用带抖动的指数退避。认证失效、账号被顶下线或服务端明确拒绝连接时返回 `AUTH_REQUIRED`，停止自动密集重试，并仅向管理员发出一次重新认证提醒。AiriCore 正常关闭时停止接收新请求，完成可结束的在途请求，并按协议支持情况关闭会话。

每个请求由序列号关联一个等待结果。超时后立即移除关联项，迟到响应只能作为过期消息丢弃，不得匹配到新的请求。未知消息和无关推送只记录脱敏消息号与长度。

## 代理策略

HTTP、catalog 和 CDN 下载统一使用 `127.0.0.1:7890` 代理。若该端口提供 SOCKS5 或 mixed 能力，TCP 游戏连接也通过同一端口建立；若只提供 HTTP 代理，则 TCP 使用直连并明确记录当前传输路径。代理能力必须在启动时探测，不能在失败后无日志地改变路径。

## 资源维护系统

### 存储结构

正式资源位于 `data/airi_astral_party/resources/`，至少区分：

- `versions/`：完成验证的资源版本
- `staging/`：正在下载和解析的新版本
- `active`：当前激活版本的原子指针或清单
- `previous`：上一完整版本的原子指针或清单
- `cache/`：按需下载的非核心素材

系统临时目录不承载任何唯一副本。研究资料继续保存在 `plugins/airi_astral_party/tmp/research/`，生产逻辑不依赖该目录。

### 更新流程

1. AiriCore 启动时查询一次资源版本，此后默认每 6 小时检查一次。
2. 比较远端版本、catalog hash 与当前激活清单。
3. 在 staging 中下载 catalog、GameData、协议描述和渲染核心素材。
4. 校验 HTTP 完整性、catalog hash、bundle 可读性、GameData 表完整性和关键素材存在性。
5. 构建 Addressables 逻辑 key 到 bundle 和资产的索引。
6. 验证通过后原子切换 `active`，原 `active` 成为 `previous`。
7. 验证失败时删除不完整 staging，继续使用旧版本。

catalog、GameData 和渲染核心素材主动镜像。其他角色立绘、皮肤和大图按查询需要懒加载到持久化缓存。这一策略与客户端按目录发现、按需取资源的行为一致，同时避免首次启动全量拉取全部 bundle。

更新期间所有查询固定读取旧 active 快照。单次查询开始后不能跨资源版本，防止新 GameData 与旧图片混用。只允许清理既非 active、也非 previous 的旧版本和可重新下载的缓存。

## 玩家查询与缓存

缓存键为 `(server, uid, feature, normalized_args)`。默认策略为：

- 总览、角色、皮肤和展示信息：5 分钟
- 对局记录：1 分钟
- 静态 GameData 查询：随 active 资源版本失效

`refresh` 绕过普通读取 TTL，但仍受同 UID 最短刷新间隔和全局请求队列限制。缓存条目包含数据采集时间、协议消息号、资源版本和公开范围，不保存完整登录包、token 或无关推送。

官服超时、代理异常或会话重连时，可以返回最近一次成功结果，并在图片或文本中标注“缓存数据”和实际采集时间。从未成功查询过时返回实时服务状态，不生成看似有效的空白结果。

请求队列设置全局并发上限、单 UID 冷却、最大积压量和单请求超时。队列满时快速返回中文繁忙提示。服务端返回无权限、非公开或空数据时原样映射为明确业务状态，不尝试其他隐藏接口。

## 图片渲染

总览、角色、皮肤、战绩、展示信息和静态资料分别使用独立模板。所有模板共享以下规则：

- 背景、角色立绘、头像、图标和稀有度标识优先来自当前客户端资源。
- 长列表自动分页，显示当前页、总页数、UID、服务器和数据采集时间。
- 服务端仅公开部分数据时显示“公开可见”标记。
- 缺失单个素材时使用统一占位元素，不让整张图片失败。
- 渲染器只接收规范化视图模型，不读取网络报文或绑定文件。
- 图片在发送前转换为 `base64://`，禁止向 OneBot 传本地路径。

图片生成或编码失败时降级为中文结构化文本。降级内容至少保留昵称、UID、关键统计、页码和数据时间。图片发送失败时只进行一次文本降级，不重复执行官服查询。

## 持久化与故障隔离

绑定、认证、玩家缓存、资源清单和素材索引分别持久化。所有可变文件使用插件级锁、脏标记和同目录临时文件原子替换。单个文件损坏时隔离该文件并恢复对应子系统，不能阻止其他子系统启动。

认证数据损坏只影响实时查询；资源索引损坏触发索引重建；玩家缓存损坏只清空玩家缓存；绑定损坏时保留坏档副本并提示管理员处理，不能静默覆盖唯一绑定数据。

## 错误处理与可观测性

用户可见错误统一为中文，并区分：参数错误、未绑定、仅支持 CN、UID 不存在、数据非公开、专用账号未认证、连接恢复中、官服超时、资源更新中和服务繁忙。

日志可以记录服务器、UID、功能、消息号、耗时、缓存命中、资源版本和脱敏异常类型。日志不得记录 token、完整 `ConnectC2S` body、设备安装标识或凭据文件内容。

插件启动时验证：

- active 资源是否完整
- previous 是否可回滚
- 凭据文件权限是否符合要求
- 代理能力和实际 TCP 路径
- 缓存文件是否可读
- 专用账号会话状态

未配置专用账号时，静态资料与资源更新继续可用。普通用户查询实时数据时收到简短状态提示，管理员只收到一次认证提醒，避免刷屏。

## 验证方案

### 命令层

- 覆盖绑定、覆盖绑定、查看绑定和解绑。
- 覆盖 `me` 与显式 UID 的所有首版子命令。
- 覆盖 CN 大小写、非 CN、非法 UID、非法页码和 `refresh` 位置。
- 验证绑定失败不修改已有数据。

### 协议层

- 使用脱敏报文验证 35 字节帧头和 Protobuf 编解码。
- 使用本地假服务端验证序列号、心跳、主动推送、拆包、粘包和请求超时。
- 验证迟到响应不会污染后续请求。
- 验证普通断线退避、认证失效熔断和正常关闭。

### 资源层

- 验证版本发现、catalog hash、bundle 完整性和 GameData 解码。
- 验证 staging 失败不改变 active。
- 验证原子切换期间并发查询仍使用同一版本。
- 验证 previous 自动回滚和懒加载素材缓存。

### 渲染层

- 验证每类卡片的空数据、单页、多页和素材缺失场景。
- 验证缓存标记、公开范围和时间字段。
- 验证最终输出为 base64，不包含本地路径。
- 验证图片失败时只发送一次文本降级。

### 官服集成

用户登录专用账号后重新采集认证流程。集成验证使用少量指定 UID，依次确认登录、心跳、总览、展示信息、角色、皮肤和战绩的实际公开范围。任何命令只在响应字段语义确认后启用；无法公开查询的数据返回明确提示，不以静态资料伪造玩家数据。

测试期间新建的临时脚本、假服务端数据和渲染产物在验证结束后删除。正式资源、凭据和运行缓存只保存在 `data/airi_astral_party/`。

## 验收标准

- AiriCore 启动后，专用账号能维持单一国服长连接并正确心跳。
- 断网恢复不会造成重复会话、请求错配或密集重登。
- `astral bind CN <UID>`、`astral me` 和 `astral CN <UID>` 使用统一目标查询链路。
- 首版玩家子命令对公开数据生成正确图片，对非公开数据给出明确说明。
- 静态命令能从当前 GameData 和客户端素材生成结果，不访问实时账号会话。
- 资源更新具有 staging 验证、原子切换和上一版本回滚能力。
- 所有图片通过 base64 发送，图片失败时有中文文本降级。
- 仓库和普通日志中不存在个人账号或专用账号凭据。
- 非 CN 输入不会发起官服查询。
