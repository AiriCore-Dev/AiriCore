# airi_security_monitor Linux AMD64 原生二进制设计

## 目标

将 `airi_security_monitor` 的全部业务源码移入插件目录的 `src/`，生产环境只加载一个面向 CPython 3.11.x、Linux AMD64 的原生 `.pyd` 二进制。二进制采用 Cython 单体扩展方案，移除普通 Python 字节码恢复路径，并通过优化、链接时优化、符号隐藏和符号裁剪提高逆向分析成本。

## 交付结构

开发仓库中的插件目录包含：

```text
plugins/airi_security_monitor/
├── __init__.py
├── _airi_security_monitor.pyd
└── src/
    ├── __init__.py
    ├── plugin.py
    ├── scanner.py
    └── build.py
```

生产发布物中的插件目录只包含：

```text
plugins/airi_security_monitor/
├── __init__.py
└── _airi_security_monitor.pyd
```

`src/` 是唯一允许编辑的业务源码位置，不进入生产发布物。生成的 C 文件、目标文件、调试信息、缓存和临时构建目录不进入生产发布物或最终插件根目录。

## 运行架构

`__init__.py` 是唯一明文运行入口，只负责以下工作：

1. 校验运行平台是 Linux。
2. 校验 CPU 架构是 AMD64，对应 `x86_64` 或 `amd64`。
3. 校验解释器是 CPython 3.11.x。
4. 定位 `_airi_security_monitor.pyd`。
5. 使用显式扩展模块加载器载入 Linux ELF 二进制。
6. 将原生模块的公共符号导出到插件包。
7. 将原生模块注册为 `plugins.airi_security_monitor.scanner` 的兼容别名。

入口不包含监控规则、配置解析、状态管理、通知逻辑或源码回退路径。平台、架构、Python 版本、文件缺失或动态加载失败时，入口抛出带实际环境信息和原始原因的中文异常，不静默降级。

原生扩展在导入时执行当前插件入口逻辑，注册 NoneBot matcher、启动钩子和关闭钩子。现有 `airisecurity` 指令、配置键、状态文件格式、告警内容、通知路由、扫描周期和冷却行为保持不变。

## 源码组织

`src/plugin.py` 保存当前插件入口、配置、状态、通知、生命周期和命令处理逻辑。`src/scanner.py` 保存安全扫描数据结构、采集器和检测规则。开发态测试直接导入 `src/` 下的模块。

构建阶段将两个源码单元合并为单个 `_airi_security_monitor` Cython 扩展。生产环境不需要单独的 `scanner.py`。扩展导出当前扫描器公共接口，并由根目录 `__init__.py` 建立旧导入路径兼容层。

任何插件变更都必须遵循固定流程：

1. 修改 `src/` 源码。
2. 对源码运行测试并确认预期失败与通过。
3. 在 Linux AMD64 CPython 3.11 构建环境中重新编译。
4. 验证新二进制。
5. 原子替换插件根目录中的 `.pyd`。

禁止直接修改、补丁处理或手工编辑 `.pyd` 构建产物。

## 构建与加固

构建目标是 CPython 3.11.x、Linux AMD64，兼容基线为 `manylinux_2_17_x86_64`。构建环境使用固定的 manylinux 容器，避免将 macOS ABI 或宿主机较新的 glibc 依赖带入产物。

Cython 构建关闭签名嵌入、源码位置嵌入、运行期源码追踪和调试能力。原生编译启用 `-O3`、链接时优化、节区拆分、无用节区回收、符号隐藏和不可执行栈。链接完成后删除调试段、局部符号和非必要动态符号，仅保留 CPython 加载所需的初始化入口及运行必需符号。

构建不得把生产密钥、`.env.prod` 内容、账号、主机名或其他环境数据固化进二进制。构建脚本使用临时目录输出，全部校验通过后才原子替换上一份可用 `.pyd`。

该方案不承诺二进制绝对不可逆。它的目标是移除明文源码与 Python 字节码恢复路径，使分析者必须处理经过优化和裁剪的 AMD64 原生机器码。

## 验证

源码测试覆盖现有扫描规则、配置解析、状态迁移、监听白名单、告警去重、通知发送和插件生命周期。行为变更遵循先失败测试、后最小实现的流程。

每次构建必须完成以下验证：

1. `file` 确认产物是 ELF 64-bit LSB x86-64 共享对象。
2. ELF 头确认目标机器为 AMD64，动态链接基线不高于 GLIBC 2.17。
3. 导出表包含 `PyInit__airi_security_monitor`。
4. 产物不包含调试段、生成的 C 源码、Python 字节码或开发机绝对路径。
5. `src/` 源码测试全部通过。
6. 在干净的 Linux AMD64 CPython 3.11 环境中仅保留 `__init__.py` 与 `.pyd`，真实加载插件。
7. 验证启动扫描、`airisecurity`、告警发送、状态保存和关闭清理。
8. 扫描生产发布清单，确认没有 `src/`、`.pyc`、生成的 C 文件、目标文件或构建缓存。

## 兼容范围

二进制支持 CPython 3.11.x，不支持 CPython 3.10、3.12 或其他 Python 实现。Python 3.11 补丁版本差异不作为单独构建维度；扩展不静态链接具体补丁版本的 `libpython`，也不使用 CPython 私有内部 API。

目标机器必须是 Linux AMD64。Windows、macOS、Linux ARM64 和其他架构会在入口校验阶段得到明确错误。

## 非目标

本次不改变安全检测规则、用户可见命令、配置项、通知路由、状态文件结构或宵禁白名单。不为其他 Python 大版本、操作系统或 CPU 架构生成二进制。不在生产环境提供源码自动回退。
