# airi_point_salad 设计规范

## 目标

在 AiriCore 中新增 `airi_point_salad` 群聊插件，实现一款以 MORE MORE JUMP！为主题的《Point Salad》卡牌游戏。插件支持 2–6 人、两种局速和两套规则，使用用户提供的角色立绘与 Logo 生成统一的精美卡面和群聊桌面图。

## 产品范围

首版包含以下四种组合：

- 快速局 × 主题原版
- 标准局 × 主题原版
- 快速局 × 混合模式
- 标准局 × 混合模式

插件只支持群聊。每个群最多同时存在一局，不提供跨群房间、私聊手牌、匹配系统、排行榜、积分货币或联网服务。

## 角色资源

六名角色分别代表一种公开收集资源：

- 花里实乃理
- 桐谷遥
- 桃井爱莉
- 日野森雫
- 初音未来
- 镜音铃

资源不使用抽象蔬菜、花朵或颜色作为主体。卡片正面使用角色完整立绘，计分信息中的资源引用使用由相同立绘制作的小型角色头像徽章。徽章同时显示专属底色和拉丁首字，保证缩小后以及色觉差异下仍可辨认。

## 核心规则

### 双面牌

每张牌有两个固定面：

- 正面：角色精美卡面，作为一张角色资源牌。
- 背面：计分条件，作为一张计分牌。

牌在当前对局中的朝向属于状态的一部分。翻面后不能恢复。

### 市场

桌面包含 A、B、C 三列。每列包含：

- 顶部一张背面朝上的计分牌。
- 下方两张正面朝上的角色牌，坐标分别为 `A1/A2`、`B1/B2`、`C1/C2`。

空位从对应牌堆补充。补牌顺序和完整牌序在创建对局时确定并持久化。

### 回合

玩家按加入顺序行动。每回合从以下行动中选择一个：

- 取得 A、B 或 C 列的一张计分牌。
- 取得任意两张当前可见的角色牌；两张牌可以来自相同或不同列。

每回合还可将自己的一张计分牌永久翻为其角色正面。翻牌不替代正常拿牌动作，每回合最多一次。

拿牌、可选翻牌和混合模式效果全部处理完毕后，市场补牌并进入下一位玩家的回合。

### 结束与结算

牌库及市场均耗尽后结束对局。每张仍保持计分面的卡牌独立结算；同一张角色资源可以同时满足多张计分牌。最终总分为全部计分牌得分、Live Mission 应援分及技能产生的明确结算修正之和。

最高分获胜。并列时依次比较：

1. 角色牌总数较多者。
2. Live Mission 数量较多者。
3. 仍并列则共同获胜。

## 局速

- 快速局：每名玩家向牌库贡献 12 张牌，预计 10–15 分钟。
- 标准局：每名玩家向牌库贡献 18 张牌，预计 20–30 分钟。

两种局速使用同一套规则和牌面，仅调整牌库规模。所有玩家数下，六种角色资源在牌库中的数量保持相等。

## 计分牌

计分条件由数据定义，首版使用五类模板：

- 收集型：每个指定角色获得固定分数。
- 配对型：每组两个指定角色获得固定分数。
- 组合型：每组三个指定或不同角色获得固定分数。
- 比较型：两个角色数量满足大于、少于或相等关系时获得固定分数。
- 风险型：指定角色加分，同时另一角色扣分。

每张卡只显示一条短规则、必要的角色徽章和醒目的分数。引擎使用结构化条件计算得分，不解析卡面文字。

牌池按玩家数和局速裁剪时遵守以下约束：

- 六种角色正面数量完全相等。
- 高波动比较牌和风险牌不超过本局计分牌的三分之一。
- 不生成无法由当前牌库规模合理满足的组合。
- 相同计分条件允许有限重复，但不会让某一角色成为明显唯一优势。

## 主题原版

主题原版只启用双面牌、三列市场、拿牌、翻牌和最终计分。它不启用 Center、技能或 Live Mission，玩法复杂度与《Point Salad》的公开信息选牌核心保持一致。

## 混合模式

### Center

开始时随机为每位玩家分配一名不重复的 Center。六名角色恰好覆盖最多六名玩家。每项技能每局只能发动一次。

- 花里实乃理｜再来一次：正常拿牌后，将本回合取得的一张角色牌放回对应市场空位，并改拿另一张当前可见角色牌。
- 桐谷遥｜冷静判断：正常行动前刷新一整列市场，然后继续本回合。
- 桃井爱莉｜完美表现：选择计分牌行动时，同时取得该列下方一张角色牌；本回合不能再翻牌。
- 日野森雫｜优雅转身：免费将自己一张计分牌翻为角色牌，不占用本回合一次普通翻牌机会，然后继续正常行动。
- 初音未来｜未来共鸣：发动时指定自己的一张角色牌和一张计分牌；最终结算该计分牌时，该角色额外视为玩家指定的任意一种角色一次。
- 镜音铃｜MORE MORE JUMP！：本回合以取得三张互不相同的角色牌替代普通拿牌行动。

技能只有在存在合法目标时才能发动。技能确认成功后才标记为已使用。

### Live Mission

桌面始终展示两张公开任务。玩家回合全部效果结束后，若满足其中一项，可领取一张任务并获得 2–4 应援分；随后立即补充新任务。每回合最多领取一张。

首版任务仅检查当前公开状态，包括：

- 拥有指定数量的相同角色。
- 拥有指定数量的不同角色。
- 拥有若干完整角色组合。
- 本回合取得指定类型或数量的卡牌。
- 当前角色数量满足简单比较关系。

任务先到先得，不包含偷牌、扣分、跳过他人回合或随机攻击效果。

## 指令

所有指令同时支持中文、英文全称和英文缩写。英文不区分大小写，解析器忽略连续空格和首尾空格。三种语言可以在同一条指令中混用。

| 功能 | 中文 | 英文全称 | 英文缩写 |
| --- | --- | --- | --- |
| 根命令 | `沙拉` | `salad` | `sl` |
| 创建 | `创建` | `create` | `cr` |
| 快速 | `快速` | `quick` | `qk` |
| 标准 | `标准` | `standard` | `std` |
| 原版 | `原版` | `classic` | `cl` |
| 混合 | `混合` | `mix` | `mx` |
| 加入 | `加入` | `join` | `j` |
| 退出 | `退出` | `leave` | `lv` |
| 开始 | `开始` | `start` | `st` |
| 拿牌 | `拿` | `take` | `ta` |
| 翻牌 | `翻` | `flip` | `fl` |
| 技能 | `技能` | `skill` | `sk` |
| 桌面 | `桌面` | `board` | `bd` |
| 规则 | `规则` | `rules` | `rl` |
| 结束 | `结束` | `stop` | `sp` |

以下创建指令完全等价：

```text
沙拉 创建 快速 原版
salad create quick classic
sl cr qk cl
```

主要操作示例：

```text
sl j
sl st
sl ta A
sl ta A1 B2
sl fl 2
sl sk
sl bd
sl sp
```

当技能需要额外参数时，`sl sk` 先返回合法目标和对应示例，玩家再发送完整技能指令。所有错误、帮助、状态与结算消息使用中文。

## 房间权限

- 创建者是房主。
- 大厅阶段任何群成员可加入，玩家可主动退出。
- 只有房主能开始对局。
- 对局开始后不能主动退出。
- 房主或群管理员可以结束对局。
- 私聊调用返回“该游戏仅支持群聊”，不创建状态。

## 视觉规范

### 卡片

- 使用约 `5:7` 的标准扑克牌比例。
- 采用已确认的 v2 设计方向：双层金色边框、清晰留白、精致但克制的装饰密度。
- 正面以用户提供的完整角色立绘为主体，配角色专属渐变、轻量光效、姓名铭牌和统一装饰框。
- 背面以计分信息为主体，使用角色头像徽章、单句规则和高对比分数。
- 不采用满圈植物线稿、密集贴纸或会与角色主体争夺注意力的装饰。
- 六名角色各有专属配色，但卡片结构、字号、信息位置和边框层级一致。
- Center 卡沿用相同设计语言，增加技能名称和一次性技能说明。

### 桌面

每次合法操作后发送一张纵向桌面总览图。信息自上而下排列为：

1. Logo、模式、局速、回合数和剩余牌库。
2. 当前玩家与 Center 技能状态。
3. A/B/C 三列市场。
4. 混合模式的两张 Live Mission。
5. 玩家顺序、计分牌数量、角色牌数量和行动标记。
6. 当前玩家的详细持牌区。
7. 本回合可用指令示例。

其他玩家只显示持牌数量，当前玩家显示计分牌与角色牌明细，避免图片无限增长。主题原版隐藏 Center 和 Live Mission 区域。最终结算图逐位显示总分、各计分牌贡献、Mission 分数、名次和并列判定。

所有发送图片在内存中编码为带 `base64://` 前缀的字符串，不发送本地文件路径。

## 模块设计

插件目录为 `plugins/airi_point_salad/`：

- `__init__.py`：插件元数据、matcher 注册和命令分发。
- `commands.py`：多语言别名规范化、参数解析和错误格式化。
- `models.py`：对局、玩家、卡牌、任务和枚举数据结构。
- `game.py`：房间生命周期、回合状态机和合法性检查。
- `cards.py`：计分条件定义、牌库构建和平衡裁剪。
- `skills.py`：六项 Center 技能和目标检查。
- `missions.py`：Live Mission 定义、达成检查和补充。
- `scoring.py`：结构化计分、明细和排名。
- `renderer.py`：卡面、桌面、帮助与结算渲染。
- `persistence.py`：原子保存、恢复、坏档隔离和过期清理。
- `assets/`：ASCII 文件名的角色立绘、Logo、头像徽章和渲染资源。

游戏引擎、计分器和命令解析器不依赖 NoneBot 事件对象，便于独立验证。matcher 只负责提取群号、用户号、昵称和管理员身份，然后调用统一服务入口。

## 状态与并发

- 对局以群号为键存储。
- 每个群使用独立 `asyncio.Lock` 串行处理状态变更。
- 非法动作在任何写入前完成检查。
- 每次合法状态变更后立即原子保存。
- 存档包含完整牌序、市场、玩家顺序、持牌朝向、当前回合、技能状态、Mission、随机种子和最后操作时间。
- Airi 启动时恢复未结束且未过期的对局，并按剩余时间恢复超时任务。
- 无法解析的存档移动为带时间戳的隔离文件，插件记录中文错误日志并以空状态继续启动。

大厅连续 15 分钟无操作自动关闭。进行中的对局连续 30 分钟无操作自动结束。任何合法操作都会刷新计时，查看桌面和规则不刷新计时。

## 渲染与性能

- 使用 Pillow 进行离线图片合成，不引入浏览器渲染依赖。
- 源立绘保存在插件资源目录，运行时不读取 Downloads 路径。
- 静态卡面按角色和规则预渲染并缓存；回合中只组合已有卡面、文本和少量状态标记。
- 字体在加载时缓存，图片对象按项目缓存策略控制常驻量。
- 桌面输出优先使用高质量 JPEG；需要透明度的独立资源使用 PNG。
- 输出前根据尺寸和字节数执行一次压缩，目标是常规桌面图不超过 3 MB。
- 图片编码为 base64 后才交给消息适配器。

## 错误处理

- 无房间、重复创建、重复加入、人数不足、非当前回合、非法坐标、重复坐标、技能无目标、技能已使用、越权开始或结束均返回具体中文提示。
- 渲染失败不提交状态变更；Airi 返回简短错误并记录异常堆栈。
- 保存失败不发送成功消息；内存状态回滚到操作前快照。
- 发送失败保留已经持久化的合法状态，玩家可用 `sl bd` 重新获取桌面。
- 自动结束失败会在下一次相关命令时再次执行清理。

## 验证标准

实现完成前必须验证：

- 2–6 人下四种模式组合均可从创建运行到结算。
- 快速局和标准局牌数正确，六种角色数量相等。
- 五类计分模板的正常值、零值、负分和边界值正确。
- 翻牌后计分面立即失效，角色面立即参与资源统计。
- 六项技能只能成功使用一次，失败尝试不消耗技能。
- Live Mission 每回合最多领取一张，并正确补充。
- 中文、英文全称、英文缩写及混合写法解析一致。
- 大小写、连续空格、非法参数和重复坐标均有确定行为。
- 同群并发拿取同一张牌时只有一个操作成功。
- 不同群对局互不阻塞。
- 保存恢复后牌序、回合、技能和 Mission 完全一致。
- 损坏存档不会阻止插件加载。
- 大厅与对局超时正确，查看类指令不刷新超时。
- 所有输出图满足扑克牌比例、桌面布局、体积限制和 base64 发送要求。
- 插件可独立加载，AiriCore 全量插件加载无新增冲突。

任务期间创建的临时验证脚本和渲染产物在验证完成后删除，不向仓库保留测试垃圾。
